# Лабораторная 3: Места — асинхронное сетевое взаимодействие

Консольное приложение на Go 1.21+. Зависимостей, регистрации и API-ключей нет.

## Запуск

```sh
cd lab3
go run ./cmd/places
# Английская Wikipedia, радиус 5 км, до 8 мест:
go run ./cmd/places -lang en -radius 5000 -limit 8
```

Введите город, адрес или название объекта (например, `Цветной проезд, Москва`,
`Новосибирск`, `Berlin`), затем номер найденной локации. Дождитесь общего отчёта.
Photon ищет по OpenStreetMap; полнота адресов зависит от карты. Места — статьи
Wikipedia с координатами, поэтому среди них бывают здания, станции и районы,
а не только достопримечательности. Русская и английская Wikipedia имеют разное покрытие.

## API

1. [Photon](https://github.com/komoot/photon), `https://photon.komoot.io/api/`:
   поиск локаций, адресов и координат. Публичный сервер предназначен для умеренного
   использования, без гарантии доступности; не запускайте массовые запросы.
2. [Open-Meteo](https://open-meteo.com/en/docs), `/v1/forecast?current=...`:
   текущая температура, ощущаемая температура, скорость ветра. Бесплатное
   некоммерческое использование без ключа; данные CC BY 4.0.
3. [MediaWiki Geosearch](https://www.mediawiki.org/wiki/API:Geosearch):
   поиск статей в радиусе 10–10000 м от выбранных координат.
4. [MediaWiki TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts#API):
   отдельный запрос краткого текстового описания для каждого найденного места.

Атрибуция: Photon / © OpenStreetMap contributors, Open-Meteo, Wikipedia.
Ссылки на исходные статьи включены в отчёт; условия лицензии доступны на страницах статей.

## Как выполнены требования

Две функции в `internal/places/service.go` возвращают Future немедленно:

- `SearchLocations(ctx, query) *future.Future[[]Location]` — поиск вариантов.
- `Explore(ctx, location) *future.Future[Result]` — получение всего отчёта.

```text
SearchLocations → Future[[]Location] → Await в консоли → выбор пользователя

Explore(location)
  ├─ GET погода ───────────────────────────────────┐
  └─ GET места → Then → GET описание 1 ─┐          │
                        GET описание 2 ─┼─ All ────┼─ All → Result
                        GET описание N ─┘          │
                                                  └─ Await в консоли → вывод
```

`internal/asynchttp` — собственная небольшая HTTP-библиотека с асинхронным
интерфейсом `GetJSON[T](...) *Future[T]`. Стандартный `net/http.Client.Do`
синхронный: адаптер выполняет транспорт и декодирование в отдельной горутине.
Прикладная логика обращается исключительно к асинхронному интерфейсу адаптера.

`Then` регистрирует продолжение, `Map` преобразует результат, `All` собирает
результаты по callback, сохраняя исходный порядок. В цепочках нет `Await`,
чтения из каналов, `WaitGroup.Wait` или ожидания других запросов в горутинах.
Короткие mutex защищают внутреннее состояние Future и агрегатора от гонок;
они не удерживаются во время HTTP или выполнения продолжений и не служат
ожиданием сетевых результатов. Промежуточные значения передаются аргументами
продолжений; глобального хранилища и состояния результатов в Service нет.

Ожидание только на границе консоли: один раз для списка локаций и один раз для
готового `Result`. Погода и поиск мест запускаются независимо; все описания —
параллельно после получения списка мест. До готовности общего объекта ничего
из отчёта не печатается. При ошибке любого запроса выводится единая ошибка,
без частичного отчёта, а контекст отменяет оставшиеся запросы.

HTTP-таймаут — 15 секунд, поиск — максимум 20, весь отчёт — 35.
Ctrl+C отменяет активные HTTP-запросы. Обрабатываются HTTP-ошибки, некорректный
JSON, ошибки MediaWiki внутри HTTP 200, отсутствие мест и пустые описания.
Для защиты от слишком больших ответов установлен лимит 2 МиБ.

## Проверка

```sh
go test -race ./...
go vet ./...
```

Тесты используют локальный HTTP-сервер без интернета. Проверяют координаты и
кодирование запроса, сбор общего результата, порядок описаний, пустые списки,
ошибки HTTP/JSON/API и отмену транспорта. Проверка параллельности устроена
через барьеры: запросы не могут завершиться, пока не стартуют независимые
запросы; последовательная реализация завершится по таймауту.

## Язык вывода

`-lang en` включает английские подсказки, справку (`-lang en -h`), сообщения
программы и итоговый отчёт. Wikipedia выбирается английская, а Photon получает
`lang=en`. Если у объекта в OpenStreetMap нет английского названия, Photon
может вернуть исходное местное название. `-lang ru` (по умолчанию) сохраняет
русский интерфейс и русскую Wikipedia.

## Константы

Константы находятся в начале файлов рядом с использующим их кодом:
- `cmd/places/run.go`: таймауты поиска и отчёта, значения и границы флагов.
- `internal/places/service.go`: таймаут HTTP, адреса API, лимиты и координаты.
- `internal/asynchttp/client.go`: размер ответа и HTTP-заголовки.
- `internal/locale/locale.go`: коды языков.

Диапазоны в справке формируются из тех же констант, что и проверка параметров.
