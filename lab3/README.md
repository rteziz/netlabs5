# Лабораторная 3: Места

Локальное веб-приложение на Go: поиск адреса, выбор локации, погода и интересные
места с описаниями. Go 1.21+, без сторонних зависимостей .
HTML, CSS и JavaScript встроены в Go-приложение через `embed`.

## Запуск

```sh
cd lab3
export GRAPHHOPPER_API_KEY="ваш-ключ-GraphHopper"
# Необязательно: только для поиска с типом места
export OPENTRIPMAP_API_KEY="ваш-ключ-OpenTripMap"
go run ./cmd/places
```

Откройте http://127.0.0.1:8080 в браузере. Введите город, улицу или объект,
нажмите «Найти место», затем выберите подходящий адрес.
Поле «Тип места» необязательно: для остановки введите название в основном поле,
а `bus_stop` — в поле типа. Оно сравнивается точно с `osm_value` GraphHopper,
например `highway=bus_stop` (здесь `highway` — ключ, `bus_stop` — значение).
При фильтрации запрашиваются до 10 кандидатов вместо 8 (лимит GraphHopper Free); это фильтр выдачи API,
а не гарантия нахождения всех объектов в мире. Если совпадений нет, уточните город.
Подсказки находятся в `internal/places/osm_types.go`; список не исчерпывающий,
другие OSM-значения можно вводить вручную. Погода и все описания
появятся единым отчётом. Можно отменить операцию, повторить её после ошибки,
сменить язык, радиус или число мест и начать новый поиск.

```sh
go run ./cmd/places -lang en -radius 5000 -limit 8
# Если порт занят:
go run ./cmd/places -addr 127.0.0.1:8081
```

Флаги задают начальные значения в браузере. `-lang en` включает английскую
справку и интерфейс; RU/EN можно переключить на странице. Радиус: 10–10000 м,
число мест: 1–10. Ctrl+C завершает сервер и отменяет активные запросы.
По умолчанию сервер доступен только на вашем компьютере.

## API и данные

- GraphHopper Geocoding: поиск адресов и координат. В английском режиме
  передаётся `locale=en`; при отсутствии перевода возможны местные названия.
- Open-Meteo: температура и ощущаемая температура (°C), ветер (м/с), давление на уровне моря (гПа), влажность (%). Используется `wind_speed_unit=ms`; ключ для погоды не нужен.
- По умолчанию (тип пустой): MediaWiki Geosearch → описания и фотографии Wikipedia.
- С выбранным типом: OpenTripMap radius: ближайшие места в выбранном радиусе (до указанного лимита).
- OpenTripMap xid: подробности каждого места, включая ссылку на Wikipedia, если она есть.
- MediaWiki TextExtracts + PageImages: описание и свободное изображение статьи по ссылке из OpenTripMap одним запросом. Если статьи нет, место остаётся в отчёте с пометкой. Фото может отсутствовать; под ним есть ссылка на страницу файла с автором и лицензией.

Ближайшие статьи могут быть о зданиях, станциях или районах. Состав мест определяется выбранным режимом; для OpenTripMap статья Wikipedia необязательна. Публичные сервисы могут быть недоступны или вернуть HTTP 429;
интерфейс показывает ошибку и предлагает повторить запрос. Автоматических повторов
нет. Не запускайте массовые запросы на публичные серверы.

Атрибуция и ссылки на источники находятся на странице; условия использования текстов Wikipedia указаны в исходных статьях, фотографий — на страницах файлов.

## Асинхронная логика

Два основных метода остались в `internal/places/service.go`:

- `SearchLocations(ctx, query) *Future[[]Location]`.
- `Explore(ctx, location) *Future[Result]`.

```text
SearchLocations -> HTTP GraphHopper -> Map -> список локаций
                                пользователь выбирает точку
Explore -> погода -------------------------------+
        -> Wikipedia geosearch -> All(описания + фото)
        либо с типом: OpenTripMap radius -> All(xid -> Wikipedia)
                    All двух ветвей -> Map -> Result
```

`internal/asynchttp.GetJSON` возвращает Future немедленно, выполняя стандартный
`net/http` транспорт в горутине. `Then` передаёт данные в зависимые операции,
`Map` преобразует результат, `All` объединяет независимые операции с сохранением
порядка. Короткие mutex защищают состояние, а не ждут сетевые ответы.

В веб-адаптере **нет Await**. POST `/api/search` или `/api/explore` запускает
цепочку и возвращает `202` с идентификатором. `OnComplete` записывает только
конечный результат операции. Браузер через асинхронный `fetch` опрашивает
`GET /api/jobs/{id}` и показывает готовый список или общий отчёт. Промежуточные
погода/описания не передаются браузеру. `DELETE /api/jobs/{id}` отменяет работу.
Промежуточные API-значения передаются внутри цепочки; таблица операций хранит
только состояние и конечный результат для доставки интерфейсу.

Запросы проверки состояния не блокируются в ожидании результата. При отмене,
смене настроек или языка браузер игнорирует устаревшие ответы. Завершённые
операции удаляются браузером; сервер ограничивает их число и срок хранения.

## Файлы и настройки

- `cmd/places/main.go`: вызов `run()` и вывод ошибки запуска.
- `cmd/places/run.go`: параметры и запуск/остановка HTTP-сервера.
- `internal/webui/server.go`: валидация, операции, отмена, выдача встроенной страницы.
- `internal/webui/static/`: интерфейс, стили и логика браузера.
- `internal/places/`: API и сборка отчёта.
- `internal/future/`: Future и продолжения.
- `internal/asynchttp/`: HTTP-адаптер.

Константы находятся в начале использующих их файлов. HTTP-таймаут — 15 секунд,
поиск — 20, общий отчёт — 35. Ограничены размеры запросов и ответов, радиус,
число мест и количество хранимых операций. Ключи читаются только из переменных окружения сервера.

## Проверка

```sh
go test -race ./...
go vet ./...
```

Тесты веб-адаптера проверяют возврат pending без ожидания, доставку общего
результата, отмену и поздние ответы, ошибки API, входные параметры,
истечение срока, ограничение числа операций и доступность встроенной страницы.
Публичные API тестам не нужны.

PDF из `output/pdf` описывает предыдущую консольную версию; после перехода
на веб-интерфейс его разделы о запуске и ожидании в консоли устарели.

Ключи: [GraphHopper](https://graphhopper.com/dashboard/) и [OpenTripMap](https://dev.opentripmap.org/). Не добавляйте их в исходники. После изменения переменных перезапустите сервер. Ключ GraphHopper обязателен для поиска адреса. OpenTripMap необязателен.

## Логи API

В терминале сервера каждый запрос получает номер: строка GET показывает URL
с замаскированными ключами, строка ответа — сервис, HTTP-статус, время выполнения
и тело ответа (до 4096 байт). Для HTTP 401/403 также выводится сообщение сервиса.
Сетевые ошибки и некорректный JSON отмечаются отдельно. Это диагностические
логи; веб-интерфейс по-прежнему показывает только целиком собранный отчёт.

Поиск мест ограничен радиусом и числом объектов (1–10), без пагинации. Без типа OpenTripMap не вызывается. С типом и ключом он получает до 12 секунд; при ошибке или пустом результате используется Wikipedia. Если ключа нет, Wikipedia вызывается сразу. Отмена общей операции не запускает запасной запрос. Все независимые цепочки работают параллельно с погодой. Wikipedia запрашивается на языке ссылки, возвращённой OpenTripMap; он может отличаться от языка интерфейса. Данные OpenTripMap распространяются по ODbL.

Тип фильтрует выбранную исходную локацию в GraphHopper. Достопримечательности вокруг неё не фильтруются по этому OSM-значению: категории OpenTripMap и Wikipedia отличаются. Источник мест отображается в общем отчёте.
