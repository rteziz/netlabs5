# Передача файлов по TCP

## Протокол

Клиент отправляет только:

| Поле | Формат |
|---|---|
| Длина имени | 2 байта, uint16 big-endian |
| Имя файла | N байтов UTF-8, 1–4096 байтов |
| Размер файла | 8 байтов, uint64 big-endian |
| Содержимое | Ровно указанное количество байтов |

Начального разрешения нет. После передачи клиент читает один байт ответа:
`0` — ошибка, `1` — файл сохранён, `2` — сервер занят.
При занятости сервер отправляет `2` сразу, закрывает направление отправки и
до секунды вычитывает входящие данные перед закрытием сокета. Этот ограниченный
период может задержать приём новых подключений до секунды; активные передачи продолжаются.
Доставка отказа при сетевом сбросе не гарантирована. При ошибке отправки клиент
пытается прочитать ответ в течение двух секунд, сохраняя исходную ошибку.
Проверка хеша всегда включена и остаётся только локальной, в сеть не передаётся.

## Запуск

Из каталога `lab2`:

```bash
go build -o client ./cmd/client
go run ./cmd/server 9000
```

В другом терминале:

```bash
./client ./4send/unknown.png 10.9.43.242 9000
```

Сервер в Docker:

```bash
docker compose up --build
```

Настройка сетевого ограничения:

```bash
RATE=40mbit docker compose up --build --force-recreate
RATE=0 docker compose up --build --force-recreate
```

Файлы сохраняются в `uploads`. Существующие файлы не перезаписываются.
Лимит размера — 1 TiB. Таймаут подключения — 10 секунд, сетевой операции —
30 секунд. Скорость выводится каждые 3 секунды и при завершении приёма.
Эти локальные проверки не добавляют полей в сетевой обмен.

`CODE_WALKTHROUGH.md` содержит исторический разбор: описанные там статусы
и подтверждения больше не используются.

## Проверка содержимого

Клиент всегда сравнивает SHA-256 файла до отправки, отправленных байтов и файла
после отправки. Дополнительно проверяется изменение размера. Флаг не нужен:

```bash
./client ./4send/unknown.png 10.9.43.242 9000
```

Хеши не отправляются по сети, формат протокола не меняется. Проверка требует
двух дополнительных чтений файла с диска. Она не блокирует изменения исходника
после последней проверки; сервер может уже сохранить файл до обнаружения изменения клиентом.

Каждый периодический и итоговый отчёт скорости содержит исходное имя файла.
До получения заголовка выводится «ожидание имени файла».
